## Сборщик - что это? 
***Сборщик веб-приложения (или bundler)*** — это инструмент, который собирает и обрабатывает файлы, используемые в веб-приложении (например, JavaScript, CSS, изображения, шрифты и другие ресурсы), и создает финальные оптимизированные файлы, которые будут развернуты в браузере для выполнения приложения

***Бандл (от англ. bundle)*** — это упакованный файл или набор файлов, который содержит объединённый код и ресурсы вашего проекта.

### Основные функции сборщика:
- Компиляция и трансформация кода
    - Например из ***tsx -> jsx -> js***
- Объединение файлов (Bundling)
    - Собирает несколько файлов (например, JavaScript, CSS) в один или несколько крупных файлов. Это позволяет уменьшить количество HTTP-запросов при загрузке страницы и улучшить производительность.
- Минификация
    - Удаление комментариев, пробелов, замена неймингов переменных
    - tree shaking (удаление неиспользуемого кода)
- Организует модульную систему
    - Позволяет организовывать код в отдельные модули, которые могут импортировать и экспортировать функциональность друг от друга.
- Генерация финальных файлов для продакшн-режима
    - В процессе сборки сборщик может генерировать файлы, которые оптимизированы для производственного окружения, например, генерировать системы кеширования с хэшами в именах файлов для обновлений или создавать карты исходников (source maps), которые помогают отлаживать приложение в браузере

### Примеры популярных сборщиков:
- Webpack

    - Один из самых популярных и мощных сборщиков для JavaScript-приложений.
    Обрабатывает JavaScript, CSS, изображения, шрифты и другие типы файлов, и позволяет гибко настроить сборку с помощью конфигурационного файла webpack.config.js.

- Parcel

    - Автоматический сборщик, который не требует конфигурации. Очень прост в использовании, поскольку автоматически определяет зависимости и настраивает сборку.
    - Инструмент для упаковки, который ориентирован на нулевую конфигурацию
    > ***Нулевая конфигурация (или zero-config)*** — это концепция, когда инструмент или библиотека работает без необходимости настройки или с минимальной настройкой сразу после установки

- Rollup

    - Сборщик, ориентированный на создание библиотек, отлично работает с ES-модулями и минимизирует количество кода.
    - Ориентирован на создание библиотек, использующий концепцию "дерева зависимостей" для оптимизации.

- Vite

    - Современный сборщик и сервер для разработки, который использует ES-модули в браузере для быстрой загрузки приложения в процессе разработки. Использует Rollup для финальной сборки.

- Esbuild
    - Это супербыстрый сборщик и транспайлер для JavaScript и TypeScript, написанный на языке Go. Он значительно быстрее большинства других сборщиков (например, Webpack, Rollup или Parcel), благодаря чему идеально подходит для современных приложений и разработки, где скорость сборки имеет большое значение.

- Gulp
    - Это инструмент, написанный на JavaScript, для автоматизации задач в процессе разработки, особенно когда вам нужно быстро и эффективно работать с файлами. Он часто используется в веб-разработке для создания задач, таких как компиляция Sass, минификация JavaScript, обработка изображений, сжатие файлов и т.д.

### **Сравнение подходов:**
- Webpack предоставляет максимально гибкие настройки, что позволяет адаптировать его под любые задачи, но для этого нужно затратить время на настройку.

- Vite идеально подходит для быстрого старта и разработки, благодаря своему подходу с использованием ES-модулей.

- esbuild — фокусируется на скорости сборки, но имеет меньше функционала и гибкости, чем Webpack.

- Parcel и Rollup также могут быть хорошими альтернативами для некоторых типов проектов, например, для библиотек.

## Как работают сборщики?

### Принцип работы Webpack

- Мы указываем входную точку (например, src/index.js).
    > Entry point - может быть несколько!

- Webpack анализирует все зависимости (import'ы, require'ы) и создает граф зависимостей.
    - ***граф зависимостей*** - рекурентое дерево, какие именно модули добавить в конечной бандл

- Затем все модули обрабатываются (с использованием лоадеров и плагинов).
    - ***лоадеры*** - это инструменты для обработки тех или иных расширений, по сути это правила обработки того или иного типа файла
    > Зачастую на данном этапе работают ***Транспиляторы*** - именно они преобразуют код
    Например: _esbuild-loader_
    - ***плагины*** - это скрипты, которые будут выполняться во время или после сборки

- В результате Webpack собирает бандлы, которые можно использовать на клиенте.

### Принцип работы Vite:

- На этапе разработки Vite не выполняет традиционную сборку, а просто использует нативные возможности браузера для загрузки и обновления модулей через ES-модули. Это позволяет значительно ускорить запуск приложения.

- Горячая перезагрузка (HMR): изменения кода сразу отражаются в браузере без необходимости полной перезагрузки страницы.

- Для продакшн-сборки Vite использует esbuild для трансформации кода и оптимизации, что также сильно ускоряет процесс по сравнению с Webpack.

### Принцип работы esbuild:

- Он делает трансляцию и упаковку с использованием многопоточности, что позволяет значительно ускорить процесс.
    - Процесс упаковки похож на работу *Webpack*
        - Анализ зависимостей - создание рекурентного дерева
        - Объединение модулей
        - Транспиляция кода
        - Минификация
        - Оптимизация (tree shaking)

- esbuild не имеет такой гибкости, как Webpack, но для большинства приложений этого достаточно, так как он решает основные задачи сборки.

- Поддерживает минификацию, разделение кода, преобразование TypeScript в JavaScript и другие функции.

## Транспиляторы

***Транспиляторы*** — это инструменты, которые преобразуют исходный код, написанный на одном языке или в одной версии языка, в эквивалентный код на другом языке или в другой версии этого языка. 

- Babel
    - это один из самых популярных транспиляторов JavaScript. Он позволяет использовать новейшие возможности языка JavaScript, не переживая о том, что эти возможности могут не поддерживаться старыми браузерами. Babel преобразует современный JavaScript (например, синтаксис ES6, ES7 и выше) в более старую версию, такую как ES5, которая совместима с большинством браузеров.

    - Основные возможности Babel:

        - Транспиляция синтаксиса (например, стрелочные функции, let/const, классы и т. д.).

        - Поддержка новых возможностей JavaScript (например, async/await).

        - Работа с JSX (для React-приложений).

        - Поддержка различных плагинов и пресетов *(ВОТ ЭТО УЖЕ ПРАВИЛА)* для кастомизации.

    - Как работает Babel:

        - Код проходит через парсер, который разбивает его на абстрактное синтаксическое дерево (AST).

        - Применяются плагины, которые заменяют новшества JavaScript на старые синтаксические конструкции.

        - Получившийся код передается в генератор, который преобразует его обратно в строку кода.

- SWC (Speedy Web Compiler)  - написан на Rust
    - Это быстрый транспилятор, написанный на языке Rust, который является альтернативой Babel. Он предлагает ту же функциональность, что и Babel, но с гораздо большей производительностью. SWC, как и Babel, поддерживает современные возможности JavaScript и TypeScript.

- Esbuild
    - Это транспилятор и сборщик, также ориентированный на максимальную производительность. Он написан на Go и предназначен для быстрого преобразования и упаковки JavaScript (и других файлов). В отличие от Babel и SWC, esbuild комбинирует функции транспиляции и сборки.

    - Особенности esbuild:

        - Очень высокая производительность, поскольку esbuild использует многопоточность и написан на Go.

        - Поддержка ES6+ и TypeScript, включая поддержку JSX и React.

        - Возможность минификации кода и разделения кода.

        - Простота в использовании и настройке, что делает его хорошим выбором для проектов, где важна скорость.
