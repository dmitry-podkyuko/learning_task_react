> Стилизация в React — это важная часть разработки, и существует несколько способов, как можно стилизовать компоненты в React. 

Рассмотрим самые популярные методы:

Группа 1
 - Самый базовый способ — подключение внешнего CSS-файла. Вы пишете CSS в отдельном файле и подключаете его в компонент.
 - Inline стили (встроенные стили)
 - CSS Modules
     - CSS Modules позволяют использовать локальные стили, которые не будут конфликтовать между собой. Каждый класс будет уникален для компонента.
 > Дополнительные инструменты: Препроцессоры (Sass/SCSS/less/stylus)

Группа 2
 - CSS-in-JS
 - Tailwind CSS
     - **Tailwind** — это утилитарный CSS-фреймворк, который позволяет писать стили прямо в JSX-разметке, используя классы.



### Сравнение подходов:
 - CSS-файлы — простота, но возможны проблемы с глобальными стилями.

 - Inline стили — быстрые и локальные стили, но ограничены возможностями CSS.

 - CSS Modules — изоляция стилей, но нужно подключать файлы для каждого компонента.

 - CSS-in-JS — динамическая стилизация с поддержкой JavaScript, но дополнительные зависимости.

 - Tailwind CSS — быстрый и гибкий подход для создания интерфейсов, но требует изучения классов.

## CSS 

Самый базовый способ задания стилей это CSS

> Но для того чтобы это работало необходимо настроить сборщик (***webpack***), если приложение создано на основе CRA или Vite - это уже работает (там уже настроено) 

## CSS Modules

Просто подключите файл CSS в ваш JSX файл ```import styles from './Button.module.css'; // подключаем файл CSS```

> Но для того чтобы это работало необходимо настроить сборщик (***webpack***), если приложение создано на основе CRA или Vite - это уже работает (там уже настроено) 

Vite использует esbuild для быстрого преобразования кода, включая CSS. Когда вы используете CSS Modules:
Каждый класс из вашего .module.css файла будет автоматически скомпилирован в уникальный идентификатор.
Vite использует стандартные практики для генерации уникальных имён классов и их добавления в HTML-код, обеспечивая изоляцию стилей между компонентами.

*[name]* — имя файла (например, Button).

*[local]* — имя локального класса (например, button).

*[hash:base64:5]* — 5-символьный хеш, который добавляется для уникальности.

Уникальные идентификаторы для классов в CSS Modules формируются с помощью генерации хешей, что гарантирует уникальность каждого имени класса на уровне компонента. Основная цель — избежать конфликтов между стилями разных компонентов, что особенно важно в больших приложениях.

Из чего он состоит:
 - Имя файла
 - Имя локального класса
 - Хеш-функция -> которая создает хеш из пунктов выше

 *Если вы хотите изменить поведение CSS Modules (например, изменить схему именования классов), вы можете настроить это в файле конфигурации vite.config.js.*
```js
// vite.config.js
export default {
  css: {
    modules: {
      // Кастомизация схемы именования классов
      generateScopedName: '[name]__[local]__[hash:base64:5]'
    }
  }
}
```

***Плюсы CSS Modules***:
 - Изоляция стилей:

Каждый компонент получает свои уникальные классы, что исключает вероятность конфликтов между стилями. Например, если два компонента используют одинаковые классы с одинаковыми именами, они не будут влиять друг на друга.

 - Управление локальными стилями:

     - Стили привязаны к конкретному компоненту, что упрощает поддержание и масштабирование приложения. Если компонент изменяется или удаляется, его стили не затрагивают другие части приложения.

 - Безопасность:

     - В отличие от глобальных стилей, где нужно следить за тем, чтобы не переопределить стили друг друга, CSS Modules автоматически генерирует уникальные имена классов, что повышает безопасность кода.

 - Поддержка динамического импорта:

     - С помощью CSS Modules можно использовать динамический импорт стилей для различных частей интерфейса, что помогает оптимизировать производительность.

 - Удобство для работы с JavaScript:

     - Используя CSS Modules, можно импортировать стили прямо в компоненты, что упрощает работу с ними. Стили становятся частью JavaScript-кода, и это удобно для работы с современными инструментами сборки, такими как Webpack.

***Минусы CSS Modules***:
 - Дополнительная настройка:

     - Для работы с CSS Modules необходимо правильно настроить сборку проекта, например, в Webpack или других сборщиках. Это может потребовать дополнительных усилий для конфигурации.

 - Ограниченная поддержка глобальных стилей:

     - Если вам нужно использовать глобальные стили (например, для шрифтов, базовых отступов или глобальных настроек), вам придется отдельно настроить поддержку глобальных стилей, что может быть менее удобно, чем с традиционными CSS.

 - Не всегда подходит для простых проектов:

     - Для небольших или простых проектов использование CSS Modules может быть излишним, так как он добавляет сложность в организацию стилей. В таких случаях проще использовать обычный глобальный CSS.

 - Нужна отдельная работа с псевдоклассами и псевдоэлементами:

     - Для использования псевдоклассов и псевдоэлементов (например, :hover, ::before) в CSS Modules нужно правильно указать их в модуле стилей. В обычных CSS это делается проще и привычнее.

## CSS-in-JS
CSS-in-JS — это подход к стилизации, при котором стили пишутся непосредственно в JavaScript, а не в отдельных CSS-файлах. Вместо того чтобы управлять стилями через отдельные CSS или SCSS файлы, в CSS-in-JS стили определяются в JavaScript коде, а затем динамически применяются к компонентам.

Этот подход особенно популярен в экосистеме React, так как он позволяет интегрировать стили прямо в компоненты, повышая модульность, реиспользуемость и динамическое управление стилями.

### Основные преимущества CSS-in-JS:
 - Локальные стили: Каждый компонент имеет свои собственные стили, и они изолированы от других компонентов, что помогает избежать конфликтов между классами.

 - Динамическая стилизация: Вы можете динамически изменять стили в зависимости от состояния компонента или пропсов. Это делает стили более гибкими.

 - Поддержка JavaScript логики: Вы можете использовать всю мощь JavaScript в CSS. Например, вычислять значения, использовать условия и циклы, обращаться к данным и т.д.

 - Меньше глобальных стилей: Благодаря тому, что стили живут внутри компонентов, вам не нужно беспокоиться о конфликте имен классов или глобальных стилей.

 - Управление темами: CSS-in-JS часто включает поддержку тем, позволяя легко менять стили всего приложения в зависимости от выбранной темы.

### Как работает CSS-in-JS?
CSS-in-JS позволяет писать стили прямо в JavaScript коде, используя различные библиотеки. Сам процесс обычно выглядит так:

 - Вы пишете стили в JavaScript в виде объектов или строк.

 - Библиотека CSS-in-JS компилирует и применяет стили к компонентам, создавая уникальные классы ( также как и CSS.module, но также добавляются *пропсы* в аргументы функции хеширования ).

 - Эти стили применяются только к нужным элементам, что предотвращает их влияние на другие компоненты.

### Преимущества и недостатки CSS-in-JS
**Преимущества**:
 - Изоляция стилей: каждый компонент имеет свои локальные стили, что минимизирует возможность конфликтов.

 - Динамическое изменение стилей: стили могут зависеть от состояния или пропсов компонента, что позволяет легко изменять их в зависимости от пользовательских действий.

 - Управление темами: легко можно создавать и управлять темами, поскольку стили можно программно изменять в зависимости от выбранной темы.

 - Модульность: стили привязаны к компонентам, что повышает читабельность и поддерживаемость кода.

**Недостатки**:
 - Производительность: в некоторых случаях может быть немного медленнее, чем традиционный CSS, из-за того, что стили генерируются динамически.

 - Отсутствие кеширования: в отличие от обычных CSS-файлов, стили, генерируемые через JavaScript, не могут кэшироваться браузером так же эффективно.

 - Отсутствие стандартных инструментов: некоторые инструменты (например, стандартные редакторы кода) могут не поддерживать автодополнение для стилей в CSS-in-JS решениях.

### Топ библиотек:
 - Styled-components
 - Emotion
 - JSS

### Настройка имени хеша в styled-components: 
 - использовать плагин ```babel-plugin-styled-components```
 ```json
 {
  "plugins": [
    ["babel-plugin-styled-components", {
      "displayName": true,
      "fileName": false // можно настроить, чтобы имя файла не включалось в хеш
    }]
  ]
}
```
 - использовать свойство displayName у созданного компонента 


## Tailwind CSS

### **Основные особенности Tailwind CSS**:
 - Утилитарный подход:

     - В отличие от традиционных CSS-фреймворков (например, Bootstrap), где стили приходят в виде готовых компонентов (кнопки, карточки, меню и т.д.), Tailwind предоставляет низкоуровневые утилитарные классы, такие как p-4 для отступов, bg-blue-500 для фона и text-center для выравнивания текста.

     > Такой подход дает полный контроль над внешним видом, позволяя кастомизировать каждую деталь интерфейса без ограничения предустановленными компонентами.

 - Быстрая разработка:

     - Благодаря утилитарным классам, разработчики могут сразу применять нужные стили, не написав ни строчки CSS. Это ускоряет процесс разработки и позволяет легко экспериментировать с дизайном.

 - Легкость в настройке:

     - Tailwind предоставляет конфигурационный файл tailwind.config.js, в котором можно настроить все параметры, такие как цвета, шрифты, отступы и прочее. Это позволяет создавать уникальные дизайны, не ограничиваясь стандартными настройками.

 - Построение адаптивных интерфейсов:

     - Tailwind предоставляет классы для создания адаптивных интерфейсов с помощью медиазапросов. Например, можно использовать классы вроде sm:text-lg, md:text-xl, lg:text-2xl, чтобы изменять размер шрифта в зависимости от размера экрана.

 - Совместимость с JavaScript-фреймворками:

     - Tailwind идеально работает с современными фреймворками, такими как React, Vue, Angular, и других, благодаря своей гибкости и минимализму.

### **Преимущества Tailwind CSS**:
 - Полный контроль над стилями:

     - Tailwind предоставляет большую гибкость и контроль над каждым аспектом дизайна, позволяя изменять любые параметры прямо в разметке.

 - Быстрая разработка интерфейсов:

     - Утилитарный подход ускоряет создание пользовательских интерфейсов, так как нет необходимости в создании или переопределении отдельных классов в CSS-файле.

 - Гибкость в кастомизации:

     - Через файл конфигурации можно изменить настройки фреймворка (цвета, шрифты, отступы, размеры и т.д.), создавая уникальные стили, соответствующие бренду.

 - Меньше повторений в коде:

     - Используя классы для каждой отдельной задачи (например, отступы, выравнивание, шрифты), вы можете избежать создания сложных CSS-классов с большим количеством повторений.

 - Поддержка JIT-режима (Just-in-Time):

     - В последних версиях Tailwind реализован JIT-режим, который компилирует только те стили, которые реально используются на странице. Это помогает уменьшить размер CSS-файла и повысить производительность.

### **Недостатки Tailwind CSS**:
 - Большое количество классов в разметке:

     - Так как стили применяются непосредственно через классы в HTML или JSX, разметка может стать перегруженной, особенно при сложных компонентах. Это может затруднить восприятие кода.

 - Порог вхождения:

     - Для новичков Tailwind может быть немного сложным для понимания, так как требует знания множества утилитарных классов и принципов, лежащих в основе фреймворка.

 - Отсутствие готовых компонентов:

     - В отличие от таких фреймворков, как Bootstrap или Material-UI, Tailwind не поставляется с набором готовых UI-компонентов, таких как кнопки, формы, навигации и т.д. Это позволяет получить больше гибкости, но также требует больше усилий для разработки компонентов с нуля.

 - Нужда в дополнительных инструментах:

     - Для эффективного использования Tailwind необходимо настроить такие инструменты, как PurgeCSS или PostCSS, чтобы исключить неиспользуемые классы и минимизировать размер финального CSS.

```html
<button class="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-700">
  Нажми меня
</button>
```
**Tailwind CSS** поддерживает кастомизацию
```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        'brand-blue': '#1e40af',
      },
    },
  },
}
```

## Препроцессоры 

**Препроцессоры CSS** — это инструменты, которые расширяют возможности стандартного CSS, добавляя новые функции и улучшения для упрощения написания и организации стилей. Они позволяют использовать переменные, вложенные правила, миксины, функции и другие возможности, которые упрощают процесс разработки и делают код более читаемым и поддерживаемым.

### **Основные препроцессоры CSS**:
 - Sass (Syntactically Awesome Stylesheets).

 - LESS.

 - Stylus.

**Преимущества использования препроцессоров**:
 - Улучшенная организация кода: Препроцессоры позволяют использовать такие функции, как переменные, миксины и вложенность, что делает код более организованным и удобным для масштабируемых проектов.

 - Снижение дублирования: Переменные и миксины позволяют избежать повторения одного и того же кода, что уменьшает избыточность.

 - Поддержка модульности: Большие проекты можно разбивать на отдельные модули, улучшая читаемость и поддержку кода.

 - Чистый и понятный код: Препроцессоры позволяют писать более понятный и чистый код, чем стандартный CSS, что упрощает его поддержку.

 - Гибкость и мощность: Функции, циклы и условия, предоставляемые препроцессорами, позволяют создавать более динамичные и адаптивные стили.

**Недостатки препроцессоров**:
 - Необходимость в компиляции: Препроцессоры требуют дополнительного шага компиляции в обычный CSS, что добавляет шаги в сборку и потенциально замедляет процесс разработки.

 - Отсутствие стандартности: Каждый препроцессор имеет свои особенности, и переключение между ними может потребовать адаптации.

 - Порог вхождения: Для новичков обучение использованию препроцессоров может занять некоторое время.

 - Перегрузка кода: Некоторые функции препроцессоров (например, вложенность) могут привести к излишней сложности кода, особенно если не следить за его чистотой.

### **Основные возможности препроцессоров**
 - **Переменные**: С помощью переменных можно сохранять значения, такие как цвета, шрифты или размеры.
 - **Вложенные правила**: Sass позволяет писать стили внутри других стилей, что помогает создавать иерархию и облегчает понимание структуры.
 - **Миксины**: Миксины позволяют создавать reusable (переиспользуемые) блоки стилей с параметрами.
 - **Наследование**: В Sass можно использовать @extend для наследования стилей от других селекторов.
 - **Функции**: В Sass можно создавать собственные функции для вычислений.

## Построцессоры 

**Построцессоры** - Это инструменты, которые применяются после написания CSS, с целью его оптимизации, минификации и улучшения производительности.

Процесс оптимизации и анализа включает в себя следующие шаги:
 - Минификация: постпроцессоры удаляют лишние пробелы, комментарии и переносы строк, сокращая размер файла и ускоряя загрузку страницы.
 - Автопрефиксеры: эти инструменты добавляют автоматические вендорные префиксы к CSS свойствам, обеспечивая совместимость стилей с разными браузерами.
 - Анализ и оптимизация: постпроцессоры могут анализировать структуру и предоставлять рекомендации по его оптимизации, такие как объединение повторяющихся стилей.

### *Доступные постпроцессоры:*
 - **PostCSS** - наиболее популярный постпроцессор

 - **CSSNano**: Это постпроцессор, который фокусируется на минификации CSS. Он удаляет ненужные пробелы, комментарии и сокращает свойства, чтобы уменьшить размер файлов.

 - **CleanCSS**: Еще один инструмент для минификации CSS, который также может оптимизировать и объединять CSS-файлы.

 - **PurgeCSS**: Этот инструмент анализирует ваш HTML и JavaScript, чтобы определить, какие CSS-классы не используются, и удаляет их из ваших CSS-файлов, что помогает уменьшить размер конечного файла.

 - **CSSTree**: Это парсер CSS, который может использоваться для анализа и оптимизации CSS. Он позволяет выполнять различные операции, такие как удаление неиспользуемых правил и оптимизация свойств.

 - **Sass**: Хотя Sass является препроцессором, он также может выполнять некоторые постпроцессорные функции, такие как минификация и оптимизация, если используется с соответствующими плагинами.

 - **Less**: Подобно Sass, Less является препроцессором, который может выполнять некоторые постпроцессорные задачи, такие как объединение и оптимизация стилей.

 - **Stylus**: Еще один препроцессор, который может выполнять некоторые постпроцессорные функции, такие как оптимизация и минификация.

 - **CSSO (CSS Optimizer)**: Это инструмент для оптимизации CSS, который может уменьшать размер файлов и улучшать производительность.

 - **Stylelint**: Это инструмент для линтинга CSS, который может использоваться в качестве постпроцессора для проверки и исправления стилей в соответствии с заданными правилами

 - **PostCSS** использует **JS** плагины для автоматизации процесса работы с CSS. Вы даже можете писать свои JS плагины и расширять библиотеку PostCSS


### *Популярные плагины:* 
 - **Autoprefixer** - автоматически добавляет вендорные префиксы к CSS свойствам, обеспечивая кроссбраузерную совместимость.

 - **PostCSS Assets** - управляет ресурсами, такими как изображения и шрифты, упрощая их подключение и оптимизацию.

 - **PostCSS Flexbugs Fixes** - исправляет известные проблемы с Flexbox в различных браузерах.

 - **PostCSS Discard Comments** - удаляет комментарии из CSS, что помогает уменьшить размер файлов.

 - **PostCSS Shorten** - сокращает CSS-свойства, упрощая код и уменьшая его объем.

 - **PostCSS Responsive Type** - автоматически изменяет размер шрифта в зависимости от размера экрана, улучшая адаптивность.

 - **PostCSS Custom Media** - позволяет использовать кастомные медиа-запросы, что делает код более гибким и удобным.

 - **PostCSS Clean** - очищает CSS от ненужных правил и свойств, улучшая его качество.

 - **PostCSS Logical Properties** - добавляет поддержку логических свойств CSS, что упрощает работу с многоязычными проектами.

 - **PostCSS Stylelint** - интегрирует линтер для CSS, что помогает поддерживать код в чистоте и соответствии стандартам.


### *Собственный плагин:* 
```js
// index.js
module.exports = (opts = {}) => {
  const prefix = opts.prefix || '';

  return {
    postcssPlugin: 'postcss-prefixer',
    Rule(rule) {
      // Добавляем префикс к каждому классу в селекторе
      rule.selector = rule.selector.split(',').map(selector => {
        return selector.trim().replace(/\.(\w+)/g, `.${prefix}$1`);
      }).join(', ');
    }
  };
};

module.exports.postcss = true;
```
```js
// postcss.config.js
const prefixer = require('./postcss-prefixer');

module.exports = {
  plugins: [
    prefixer({ prefix: 'my-prefix-' }), // Укажите префикс, который вы хотите добавить
    // Другие плагины PostCSS могут быть добавлены здесь
  ]
};
```
